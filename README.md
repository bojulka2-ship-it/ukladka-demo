## Деплой: GitHub Pages (демо)

Сайт полностью статический, все пути **относительные** — из корня любого репозитория он открывается как есть, сборка не нужна.

### Вариант A — отдельный публичный репозиторий (рекомендуется)

Как у демо завода `tver-stone-demo`: чистый URL, в репо только сайт.

1. Создать пустой публичный репозиторий, например `ukladka-demo`.
2. Скопировать **содержимое** `Ukladka/` в корень нового репо (без самой папки `Ukladka`).
3. Запушить в ветку `main`.
4. GitHub → **Settings → Pages → Build and deployment**:
   - Source: **Deploy from a branch**
   - Branch: `main` / folder: **(root)**
5. Через 1–2 минуты сайт: `https://<user>.github.io/<имя-репо>/`
6. Проверить: главная, три статьи, картинки, кнопки «Позвонить».

### Вариант B — подпапка в основном репозитории завода

1. Скопировать папку `Ukladka/` в корень основного репо (например, `Z3/Ukladka/`).
2. Запушить.
3. Pages на **том же** репо должен быть включён (Settings → Pages → Deploy from a branch → `main` / root).
4. Адрес: `https://<user>.github.io/<репо-завода>/Ukladka/`
5. Главная репо при этом будет отдавать основной лендинг/файлы завода — это нормально, но URL демо получается длиннее.

### Локальный просмотр (без деплоя)

Открыть файл напрямую: `Ukladka/index.html` в браузере.  
Либо из папки проекта: `npx serve .` / `python -m http.server 8080`.

## Ограничения: чего нет для полноценного запуска

Демо пригодно для показа и «картинки». Для рабочего сайта заказчику не хватает следующего.

### 1. Сбор заявок (главное)

- **Нет формы** — по ТЗ демо; на боевом сайте нужна форма (как в `Z3`) или иной канал лидов.
- **Нет страницы политики ПДн** (`policy.html`) — обязательна при наличии формы и полей ФИО/телефон (152-ФЗ).
- **Нет серверной отправки** — `send.php` / Netlify Function / почта менеджеров.
- **Нет honeypot, rate-limit, серверной валидации** — будут нужны с формой.
- WhatsApp-кнопка в блоке CTA **не ведёт в WhatsApp** — сейчас второй CTA тоже `tel:` (номера WA нет).

### 2. Контакты и реквизиты

- Телефон — **заглушка** `+7 (900) 000-00-00`, заменить на реальный.
- Нет e-mail, точного адреса, карточки организации, ИНН/ОГРН (для юрлица в футер/контакты).
- Режим работы и «завод в 15 км от Твери» — текст из брифа, не подтверждены.

### 3. Контент и доверие

- **Портфолио — не реальные объекты**: картинки из `Ukladka.md` (внешний генератор), не фото работ завода. Для боевого сайта нужны фото заказчиков с подписями (адрес/площадь/срок).
- Цены «от 3 200…» и «актуальны на 2026» — без синхронизации с прайсом; при изменении цен правится вручную в `index.html` и `statya-ceny.html`.
- Срочный блок жёстко про **«до 30 сентября»** и «12 слотов» — после даты текст устареет; нужен либо шаблон с датой заказчика, либо нейтральная формулировка.
- Статьи без ссылок на первоисточники и без юридической вычитки (для публичного блога может потребоваться проверка утверждений о ценах и гарантиях).
- Нет отзывов/кейсов с именами (в отличие от основного лендинга) — опционально, но влияет на конверсию.

### 4. Техническое (для боевого, не для демо)

| Что | Сейчас | Для запуска |
|---|---|---|
| Домен | только `*.github.io` | свой домен заказчика + HTTPS |
| Favicon / og:image | нет | иконка, превью для соцсетей |
| robots.txt / sitemap.xml | нет | добавить перед индексацией |
| Аналитика | нет (по ТЗ демо) | Яндекс.Метрика / цели, если нужно |
| Размер файлов | `css/style.css` ≈ 26 КБ; часть `img/*.png` 100–170 КБ | для жёстких лимитов РФ-фильтров (≤21 КБ/файл) — пережать в webp/avif и разбить CSS |
| Сжатие/Brotli | зависит от хостинга | на нормальном хостинге включить |
| Тесты / CI | нет | опционально |

### 5. Процессное

- Папка `Ukladka` **не является git-репозиторием** — перед деплоем инициализировать или копировать в существующий репо.
- Нет инструкции/договорённости, **кто владелец** демо-репо (личный аккаунт vs организация).
- Нет отдельного окружения Netlify/Vercel — если позже нужен сервер, это новый проект (как `tver-stone`), из этого демо тянуть нечего.
